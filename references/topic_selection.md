# 微信公众号智能选题规约 (Topic Selection Rules)

> 本规范指导公众号选题发掘、素材匹配与历史文章去重，供 `wechat-creator` 技能按需引用。

---

## 一、 选题的核心定位：Topic 与 Title 的分离

选题（Topic）解决的是**“写什么”与“提供什么信息增量”**，标题（Title）解决的是**“文章最终叫什么”与“如何呈现价值锚点”**。

在选题阶段，严禁直接堆砌 10 个吸睛标题交差。一个合格的选题必须明确：
1. **核心话题与切入角度**；
2. **读者为什么值得看**：可以是实用收益、经验借鉴、信息增量、观点启发或情绪共鸣；
3. **作者具备的真实素材或经验支撑**。

---

## 二、 基础智能选题（无 MCP 环境）

当未连接星河文场 MCP 时，选题严格基于以下公开与即时信息发掘，绝不虚构历史数据库或假装读取了用户过往文章：
1. **用户当前对话中提供的领域、经历或笔记**；
2. **公开的技术、行业动态或常见认知误区**；
3. **明确的目标受众画像与核心痛点**；
4. **具体落地场景而非空泛的宏观话题**。

---

## 三、 星河文场 MCP 增强智能选题（MCP 连接环境）

当连接星河文场 MCP 时，优先调用平台实际支持的工具，实现高度个性化且具有连续性的选题规划：

```text
get_writer_profile() [作者画像与偏好]
          +
search_materials()   [私有素材与踩坑笔记]
          +
list_articles()      [历史发布记录]
          ↓
发掘候选选题 (Candidate Topics)
          ↓
历史文章比对与去重 (Deduplication)
          ↓
评估真实素材充分度
          ↓
输出高价值下一篇建议
```

### 1. 候选选题来源优先级
1. **作者近期真实经历与踩坑复盘**（最高权重）；
2. **私人素材库中沉淀的灵感卡片、数据摘录或案例**（调用 `search_materials`）；
3. **最近完成的项目、工具评测或业务交付**；
4. **历史文章中未展开的子分支或出现的最新进展**（调用 `list_articles`）；
5. **读者或用户高频咨询的痛点问题**；
6. **行业或开源生态出现的确定性新版本/新工具**。

*降低优先级*：无个人素材支撑的泛热点、宏大空洞的行业趋势、与作者长期定位无关的抓眼球话题。

### 2. 历史文章语义去重与信息增量评估

当连接星河文场 MCP 且能够读取历史文章数据时，严格执行**语义去重**，防范同质化选题。

#### ① 语义维度的综合判定（严禁仅比对标题文本）
历史文章去重绝不能只机械比对标题字符串。若 MCP 工具允许读取历史文章的摘要、正文、核心观点或详情（如先调用 `list_articles` 获取标题与摘要，必要时调用 `get_article` 读取完整正文），必须优先综合判断：
- **标题与摘要**
- **核心论点与文章结论**
- **主要事实、案例与论据**
- **解决的目标读者问题**

> **典型场景辨析**：
> 两个标题文字差异很大，但可能属于同一个 Topic。
> 例如：“我做了一个公众号工具” 与 “花了几个周末，我做了一个 AI 创作平台”。
> 表面看词汇完全不同，但若两篇核心都在讲述“从零开发一款面向公众号创作者的 AI 辅助工具的个人经历”，应判定为高度重合的同一选题，必须进行去重或视角重构。

#### ② 重复判断的核心关注维度
对比候选选题与历史文章时，重点核对以下 8 项：
1. **核心问题是否相同**：是否在解决读者面临的同一个疑问或痛点；
2. **核心观点是否相同**：文章主张的结论或主旨是否高度雷同；
3. **主要事实或案例是否重复**：是否复用了相同的故事、人物、项目或代码经历；
4. **是否存在新的产品/业务进展**：相比上次发布，是否有新的版本、阶段性突破；
5. **是否存在新的真实数据**：是否有新增的用户反馈、转化指标、性能对比或运营数据；
6. **是否有新的踩坑经验**：是否有过去未提及的真实教训与技术避坑经验；
7. **是否产生了新的认知结论**：实践后是否验证了新规律，甚至修正了旧观点；
8. **新文章能否提供真实的信息增量**：读者读完新篇，能否获得此前从未获得的确定性收益。

#### ③ 从“被动禁止”到“良性演进”：信息增量转化
核心原则：
> **不要仅因为历史标题不同，就判断为新选题；也不要仅因为主题相同，就禁止继续写。真正判断的是“是否存在新的信息增量”。**

如果候选选题与历史文章 Topic 相同，但具备显著的**新信息、新事实或新认知**，绝不能简单判定为“不能写”，而应将其引导转化为高价值的良性延续作品：
- **后续进展**（如《上线两个月后的真实留存数据与复盘》）；
- **新版本复盘**（如《推翻旧设计：V2 架构演进实录》）；
- **阶段总结**（如《从 0 到 1000 用户的阶段性关键决策》）；
- **踩坑补充**（如《避坑补遗：上篇文章没聊透的 3 个关键雷区》）；
- **新结论 / 观点修正**（如《一年前我的架构设计错了：经过实战检验的新结论》）；
- **系列文章下一篇**（如《实战系列第 2 篇：从原型到生产级交付》）。

若既无新进展又无新观点，仅为“换个说法表达相同内容”（换汤不换药），则果断剔除，推荐全新切入方向。**真实性约束**：只有当 MCP / 历史文章工具真实返回历史文章标题时，才可以明确展示旧文标题；如果只能判断主题高度重复，但没有拿到可靠标题，不得自行编造历史文章标题。

## 四、 选题输出格式规范

当用户明确要求“推荐选题”或“找方向”时，默认输出 5~8 个可写度高的具体选题。**如果真正高质量、素材充分的候选不足 5 个，不要为了凑数量生成低质量选题（质量优先于数量）**。严禁输出任何虚假精确度评分（如“爆款指数 92%”、“热度 88”），采用客观的状态标签说明。

### 单个选题标准格式

```markdown
### 1. [选题名称]
- **核心角度**：[本文切入的具体矛盾、视角或落地场景]
- **价值主张**：[读者为什么值得看：实用收益 / 经验借鉴 / 信息增量 / 观点启发 / 情绪共鸣等]
- **目标受众**：[最适合哪类人群阅读]
- **文章类型**：[经验复盘 / 教程指南 / 观点洞察 / 工具评测 / 深度科普 等]
- **素材情况**：[已有私域素材 / 依赖公开事实 / 需要额外调研]
- **历史关联**：[首次创作 / 旧文续篇 / 系列规划]
- **状态标签**：[素材充分 / 建议优先写 / 需补充调研 / 适合做系列]
```

---

## 五、 一键选题并直接写作（自适应流水线）

当用户发出“帮我选个最合适的方向直接写”、“一键生成一篇”等指令时：
1. 快速完成选题分析，筛选出**真实素材最充足、与作者定位最匹配**的单个选题；
2. 向用户简要说明选定该方向的依据（2~3 句）；
3. 无需在此停顿或强制大纲确认，直接平滑衔接后续的事实调研、正文写作、去 AI 味与标题封面规划全流程。
