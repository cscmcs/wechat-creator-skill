# 微信公众号文章组织与思考框架 (Structure Frameworks)

> 本规范提供 11 种经典写作思考框架与移动端行文准则，供 `wechat-creator` 技能按需引用。

---

## 一、 最高准则：内容优先于结构

文章的结构是为传达信息和观点的清晰度服务的，**框架是思考工具，绝非机械模板**。

### 允许的行为
* 根据内容实际情况自由删减、合并或调换框架中的步骤；
* 混合使用多种结构的优点（如在教程中穿插经验复盘）；
* 在材料简单清晰时，采用极简的自然推进，完全不套用任何预设框架。

### 严格禁止的行为
* **禁止强行三段论**：不要机械地将所有论点凑成“1、2、3 点”；
* **禁止强行制造冲突与焦虑**：若事实平实，不要为了吸引眼球捏造对立面；
* **禁止强行编造故事与人设**：没有真实个人故事时，直接陈述逻辑与事实，不编造虚假亲身经历；
* **禁止刻板反转**：不要滥用“然而事实真的如此吗”、“你以为是 A，其实是 B”等套路；
* **禁止虚假总结升华**：结尾直接自然收拢，不强行拔高到人生哲学或时代宏大叙事。

---

## 二、 移动端阅读的自然节奏

公众号的核心阅读场景是移动端手机屏幕，行文应遵循以下自然节奏：

1. **自然段落**：
   * 允许单句短段、2～4 句正常段落和少量较长段落；一个段落也可以只负责叙事、描述、举例或补充过程；
   * 连续 4 个以上单句段落时检查是否切得过碎，多个段落长度接近时按语义合并或调整，不把“移动端友好”理解为每句话单独成段；
   * 警惕在手机屏幕上连续占满数屏的大面积密集黑块。
2. **长短句交错**：
   * 核心论点与关键动作使用凝练短句；
   * 背景交代与逻辑因果可使用完整复句，形成自然的语流起伏。
3. **真实细节优先**：
   * 优先引用材料中已有的具体数字、真实工具名、具体报错信息和真实时间线；
   * 素材未包含细节时，保持克制与严谨的概括推演，绝不添枝加叶编造伪细节。

## 三、 先看素材，再定写法与篇幅

写作前把可用材料分成三类：已核实的外部事实、作者亲自提供的观察与判断、尚待确认的个人细节。公开产品资料能支撑功能说明，不能自动支撑“我为什么开发它”“用户怎样评价它”等第一人称叙述。

* **素材足够**：选一个最有信息量的具体切口，围绕真实过程、判断或事实推进。不要为了覆盖所有功能，把文章写成按模块排列的说明书。
* **只有公开事实或功能清单**：可以写产品介绍或使用说明，明确功能边界；不要虚构开发动机、亲历场景和用户反馈，也不要用“你可能遇到过……”填满开头。
* **用户要求个人口吻或较长篇幅，但缺少第一手材料**：先问一两个会改变正文的具体问题，例如“你做这个功能时放弃了哪种方案？”“最近一次实际使用中，你改掉了哪句生成内容？”同时完成可核验部分。若未得到补充，按现有材料能支撑的长度写；若达不到用户明确的字数下限，说明缺口并继续索取材料，不能把不足字数的草稿当作已完成成稿，也不能靠同义重复凑数。
* **作者提供旧文或表达样本**：从中归纳可观察的句式、用词与节奏，只借表达习惯。不能复制旧文的案例、数字或观点到新主题，也不能把平台默认画像当成真实样本。

成稿后再读一遍每段：它是否提供了新事实、新判断、必要解释或可执行信息？如果只是换一种说法重复前段，就删掉。段落长短和小标题数量由内容决定，不人为制造参差或固定节奏。

## 四、 11 大经典写作思考框架 (Thinking Frameworks)

根据文章的核心诉求，可选择以下框架作为构思起点：

### 1. 经验分享框架 (Experience Sharing)
* **思路**：真实踩坑与做法对比。
* **思考节点**：遇到的真实问题 -> 实际做法与过程 -> 具体动作及结果 -> 已知边界 -> 现状。只有素材里确有转机时才写转折。

### 2. 实操指南框架 (How-To / Step-by-Step)
* **思路**：目标明确、步骤可落地的教程。
* **思考节点**：预期效果与产出 -> 前置准备与环境依赖 -> 核心步骤分步演练 -> 常见卡点排查 (Troubleshooting) -> 进阶建议。

### 3. 观点洞察框架 (Opinion & Insight)
* **思路**：针对现象或行业趋势的独到判断。
* **思考节点**：关注的焦点现象 -> 亮明核心判断与态度 -> 支撑依据（事实、数据与逻辑） -> 深层动因分析（成本、供需或机制） -> 应对建议与冷思考。

### 4. 产品评测框架 (Product Review)
* **思路**：客观中立的工具与产品上手体验。
* **思考节点**：解决谁的什么麻烦 -> 2~3 个核心亮点与实际场景 -> 真实体验中的短板与不足 -> 适用人群与版本选择建议。

### 5. 个人叙事框架 (Personal Narrative)
* **思路**：基于真实经历的心路与决策复盘。
* **思考节点**：真实起点或场景 -> 发生过的动作与过程 -> 已知结果或当前状态。无需凑关键契机、认知收获或结尾嘱咐。

### 6. 行业观察框架 (Industry Analysis)
* **思路**：前沿动态与生态演进解剖。
* **思考节点**：近期代表性事实信号 -> 串联背后的共同脉络 -> 不同参与方的处境与博弈 -> 短期演变推演 -> 确定性与不确定性边界。

### 7. 技术原理解析框架 (Technical Deep Dive)
* **思路**：剥离复杂表象，讲清底层机制。
* **思考节点**：传统方案的痛点 -> 核心机制的原理解释与直观类比 -> 关键数据流或交互链路 -> 架构设计的权衡取舍 (Trade-offs) -> 工程实践启示。

### 8. 知识科普框架 (Educational Primer)
* **思路**：抹平认知信息差，通俗化新概念。
* **思考节点**：该概念与读者的实际关联 -> 常见直觉误区剖析 -> 剥离黑话讲清本质 -> 典型应用实例 -> 一句话要点备忘。

### 9. 案例拆解框架 (Case Teardown)
* **思路**：拆解标杆项目的运转逻辑。
* **思考节点**：项目基本面与定位 -> 差异化突破口 -> 运转与增长链条 -> 普通人或小团队的可借鉴之处 -> 关键壁垒与不可复制的偶然因素。

### 10. 避坑纠偏框架 (Pitfall Avoidance)
* **思路**：揭示隐性成本，校准认知盲区。
* **思考节点**：普遍存在但代价高昂的做法 -> 还原真实代价与瓶颈 -> 经过验证的反直觉真相 -> 纠偏行动步骤。

### 11. 阶段复盘框架 (Retrospective)
* **思路**：周期性成长、项目结项与得失总结。
* **思考节点**：周期内的核心目标与达成 -> 超预期的动作与亮点 -> 遗憾与踩坑事项 -> 深入根本归因 -> 下阶段的核心聚焦。
