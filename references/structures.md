# 微信公众号核心写作规约 (Writing Core Rules)

> 本规范为系统写作核心标准，供 `wechat-writer` Skill 与 Web 端写作引擎统一引用。任何针对文章生成的规则调整均在此集中维护。

---

## 一、 移动端阅读三大基本法则

微信公众号 90% 以上的阅读发生在手机竖屏环境。文章必须优先考虑：**移动端节奏、信息密度、阅读呼吸感与真实可信度**。

1. **短段落与呼吸节奏**：
   - 手机屏幕有效视口较小，单段原则上控制在 **1~4 句话**（约 50~120 字）。
   - 严禁出现连续超过 5 行、毫无视觉喘息的密集大黑块段落。
   - 句子长短自然起伏，避免把每一句都切成机械单行，也避免冗长嵌套长句。

2. **事实与真实素材边界（不可逾越的红线）**：
   - **真实优先**：优先使用输入中已有人物、真实经历、明确数据、真实产品、具体场景、反馈对话与时间线。
   - **严禁虚构伪细节**：素材未提供时，不得为了显得真实而捏造：
     - 虚构的朋友、同事、客户、合伙人或采访对象；
     - 精确的虚假收入、营业额、用户量、翻倍比例、测试次数与效率提升百分比；
     - 虚构的聊天记录、事故现场、情绪崩溃或戏剧性反转；
     - 细致的感官动作描写（如“窗外雨水顺着玻璃滑下”、“他狠狠掐灭了烟头”）。
   - **素材不足时的应对策略**：进行概括性逻辑推演、说明适用前提与边界条件，或直接剔除没有根据的断言；绝不编造假细节，也绝不在正文中输出“因素材不足无法撰写”。

3. **彻底杜绝典型 AI 套话与机械句式**：
   - **机械结构连接词**：严格限制使用“首先、其次、再次、最后、总而言之、综上所述”。（若在操作指南步骤中自然标号则允许）。
   - **宏大空洞的时代叙事**：禁止使用“在这个飞速发展的时代”、“随着人工智能浪潮席卷而来”、“在这个瞬息万变的世界里”。
   - **伪深刻反转句式**：禁止连续使用“真正的 XX 不是 XX，而是 XX”、“你以为是 XX，其实是 XX”、“这不仅是 XX，更是 XX”。
   - **空泛黑话**：禁止堆砌“认知突围、底层逻辑、赋能闭环、核心抓手、顶层设计、全域破局”等无信息增量的词汇。
   - **说人话、重直接**：专业概念用平实的口语化语言解释清晰，不装腔作势。

## 二、 微信公众号 11 大经典文章结构体系

写作前必须根据文章类型与核心诉求选择最合适的逻辑结构，杜绝千篇一律的“痛点 -> 三点建议 -> 总结升华”模板：

### 1. 经验分享型 (Experience Sharing)
- **适用场景**：个人踩坑心得、实操经验、真实成长复盘。
- **结构骨架**：
  1. **现实切入**：直接说明踩过的坑或得到的具体结论。
  2. **核心转折**：过去的做法 vs 带来改变的关键动作。
  3. **3~4 个真实原则/动作**：结合具体做法说明如何落地。
  4. **边界与代价**：坦白说明该方法的局限性、适用人群与潜在成本。
  5. **自然收尾**：总结当前状态，不强制打鸡血。

### 2. 教程指南型 (How-To / Step-by-Step)
- **适用场景**：工具使用、环境搭建、新功能上手、工作流搭建。
- **结构骨架**：
  1. **目标与效果**：完成本教程能得到什么确切成果（输入/输出对比）。
  2. **准备前提**：前置依赖、耗时预估、成本或工具准备。
  3. **分步操作 (Step 1, Step 2, Step 3)**：步骤清晰，说明输入什么、点击什么、注意什么。
  4. **常见避坑清单 (FAQ / Troubleshooting)**：新手最容易卡住的 2~3 个问题。
  5. **进阶建议**：后续优化方向或下一步行动。

### 3. 观点洞察型 (Opinion & Thought Leadership)
- **适用场景**：行业趋势观察、针对热点事件的独到分析、争议话题探讨。
- **结构骨架**：
  1. **提出焦点**：开门见山点出正在发生的现象或普遍认知。
  2. **亮明观点**：给出自己的核心判断，不含糊其辞。
  3. **论证支撑一（事实与现象）**：列举真实发生的案例与事实逻辑。
  4. **论证支撑二（深层动因）**：为什么会这样，背后的供需、成本或人性动力。
  5. **应对建议与冷思考**：对读者的实际影响是什么，接下来该怎么做。

### 4. 产品介绍与工具测评 (Product Review & Demo)
- **适用场景**：新工具发布、软件评测、效率神器推荐。
- **结构骨架**：
  1. **核心定位**：这款工具到底帮谁解决什么具体麻烦。
  2. **高光亮点 (Feature Highlights)**：最惊艳或最实用的 2~3 个核心功能（搭配场景）。
  3. **真实体验优缺点**：好用的地方有哪些，尚未成熟或难用的地方在哪里（保持客观）。
  4. **性价比与版本选择**：免费版够不够用、付费版适合谁、替代品对比。
  5. **上手建议**：建议谁立即尝试，谁可以暂时观望。

### 5. 个人故事型 (Personal Narrative)
- **适用场景**：个人经历、转型转行、创业历程、独立开发心路。
- **结构骨架**：
  1. **起点与背景**：当时所处的真实境况与遇到的阻碍。
  2. **关键决策点**：为什么决定做出改变，当时权衡了什么。
  3. **经历中的波折**：遇到的真实意外与解决过程（有具体细节）。
  4. **现在的认知与收获**：做完这件事情后，对自己与生活的重新理解。
  5. **给同路人的一句话**：平实真诚的嘱咐，不作空洞说教。

### 6. 行业观察与趋势分析 (Industry Analysis)
- **适用场景**：科技动态、新商业模式拆解、生态演进分析。
- **结构骨架**：
  1. **关键信号**：近期行业内发生的几起代表性事件。
  2. **底层脉络**：这些事件串联起来反映了什么共同趋势。
  3. **各方博弈**：巨头、创业者、普通用户的不同处境与诉求。
  4. **未来推演**：短期内可能发生的演变与潜在机遇。
  5. **判断边界**：哪些是确定性的，哪些仍存在高度不确定性。

### 7. 技术原理解析 (Technical Deep Dive)
- **适用场景**：架构剖析、算法机制解读、底层代码解析。
- **结构骨架**：
  1. **为什么需要它**：传统方案遇到了什么瓶颈（性能、复杂度、成本）。
  2. **核心概念通俗化**：用一个贴切的现实类比解释核心机制。
  3. **关键流程解剖**：核心交互、生命周期或数据流转链条（配合流程图）。
  4. **权衡取舍 (Trade-offs)**：采用了该方案带来了什么优势，牺牲了什么。
  5. **落地启示**：在实际业务开发中该如何借鉴。

### 8. 知识科普型 (Educational Primer)
- **适用场景**：新概念解读、专业知识通俗化、信息差抹平。
- **结构骨架**：
  1. **日常生活直击**：为什么这个概念与普通读者息息相关。
  2. **常见误区粉碎**：大多数人对这个概念的直觉误解。
  3. **核心本质讲解**：剥离复杂术语，用人话说清底层原理。
  4. **应用场景示例**：在现实生活中会在哪里遇到或应用。
  5. **一句话备忘卡**：用一句话记住核心要点。

### 9. 案例拆解型 (Case Teardown)
- **适用场景**：爆款产品剖析、出海成功项目复盘、典型打法研究。
- **结构骨架**：
  1. **项目画像**：产品是什么、数据表现如何、背后的操盘团队。
  2. **差异化定位**：在竞争激烈的市场中找到了什么切口。
  3. **核心飞轮**：获客、留存与变现的关键链条。
  4. **可复用打法**：普通人或小团队能直接借鉴的 2~3 个具体点。
  5. **抄不走的壁垒**：该项目的关键壁垒与外部运气成分。

### 10. 认知迭代 / 避坑指南 (Pitfall Avoidance & Lessons)
- **适用场景**：复盘教训、反直觉常识普及、思维认知纠偏。
- **结构骨架**：
  1. **普遍陷阱**：很多人深信不疑但实际危害很大的做法。
  2. **代价还原**：这样做为什么会走入死胡同（真实成本与后果）。
  3. **反直觉真相**：经过验证的实际有效逻辑。
  4. **纠偏行动指南**：如果正在踩坑，从明天开始第一步应停止做什么、开始做什么。
  5. **自检清单**：供读者自测的 3 个检查问题。

### 11. 个人复盘型 (Retrospective)
- **适用场景**：月度/年度复盘、项目结项复盘、阶段性成长汇报。
- **结构骨架**：
  1. **整体概览**：周期内的核心目标与最终达成情况。
  2. **超预期与亮点**：做对了什么、哪些尝试产生了意外收获。
  3. **失误与遗憾**：踩了什么坑、哪些决策导致了资源浪费。
  4. **根本归因**：不是浮于表面的理由，而是深层次的习惯或认知根源。
  5. **下一阶段唯一聚焦**：下个阶段只全力解决的一两个核心问题。

## 三、 微信排版导向的 Markdown 格式规范

1. **二级标题**：必须使用 `## 标题文本`。标题应具有信息量，避免“第一部分”、“引言”。
2. **三级标题**：必须使用 `### 小标题`，适用于更细粒度的展开。
3. **重点金句**：只对正文中原生存在的核心论点使用 `> 引用文本`。
4. **操作提示**：对关键注意点、避坑指南使用 `> [!TIP] 提示文本` 或 `💡 提示：文本`。
5. **配图占位**：如需配图，使用标准格式 `[配图建议: 画面内容与构图说明]` 或 `![图片描述](url)`。
6. **结尾落款**：文章按内容自然收尾，不强制要求点赞在看三连。
